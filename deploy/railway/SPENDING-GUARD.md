# Private OpenAI spending guard

This fork keeps the AgentMemory runtime at **0.9.27** and runs a deployment-only gateway in the same container. AgentMemory memories still use iii-engine; the separate SQLite file is exclusively an admission ledger for OpenAI spending.

## Enforced allowance

Every upstream attempt reserves a strict upper bound on its own cost **before** network access: a token is at least one UTF-8 byte, so the forwarded body's byte length bounds input tokens, and chat output is bounded by its `max_tokens`. A response whose reported usage costs more than its reservation freezes the ledger. A SQLite `BEGIN IMMEDIATE` transaction shares the allowance across concurrent requests and gateway processes. Committed reservations survive restarts. Failed requests, lost responses and retries are not refunded.

No more than US$40 of reservations may be admitted in a rolling 35-day window (US$30 until the owner raised it on 2026-10-09, while the window was still full of the old flat reservations). This is deliberately more conservative than a calendar-month bill, and billed usage can never exceed admitted reservations. Until 2026-10-09 every attempt reserved a flat US$0.03 (chat) or US$0.01 (embedding); at one embedding per recorded observation that exhausted the allowance in about ten days while real usage stayed in cents. A per-request bound never exceeds those flat amounts (the largest admissible chat body reserves under US$0.018, the largest embedding body about US$0.002). Startup logs the US$ reserved in the current window.

Only `/v1/chat/completions` using `gpt-4o-mini` and `/v1/embeddings` using `text-embedding-3-small` are accepted. Chat is text-only, one completion, at most 4,096 output tokens, with standard service tier forced. Bodies are capped at 100,000 bytes. Embeddings accept at most 128 nonempty strings, each at most 8,000 UTF-8 bytes, within the aggregate body limit. Unknown fields, other models/routes, images, tools, token arrays and redirects are blocked.

At the reviewed rates (US$0.15/million input and US$0.60/million output tokens), even 128,000 chat input tokens plus 4,096 output tokens cost US$0.0216576. Embeddings cost US$0.02/million tokens; their admitted input bound is below the US$0.01 reservation. No discounts or usage-report refunds are assumed. Rates were reviewed on 2026-09-06 and again on 2026-10-09 (unchanged, per the gpt-4o-mini and text-embedding-3-small model pages); **paid requests stop on 2027-01-01 UTC until the policy is reviewed and its date updated**. Do not extend this date without checking prices and token bounds. An unannounced pricing change within the approval interval remains an external assumption; this is not a guarantee against arbitrary provider repricing or user changes to the guard.

Use a dedicated OpenAI project/key solely for this deployment. A native OpenAI **enforced** limit a little above the guard's cap (for example US$45), where available, provides a second control; alerts alone do not stop usage, and provider enforcement can be delayed. Neither unrelated OpenAI projects nor Railway hosting nor taxes are counted by this deployment's ledger. Do not share this key with other clients.

## Credentials and process boundary

The root-owned supervisor reads the real Railway `OPENAI_API_KEY` and starts a gateway on `127.0.0.1:3114`. Its unprivileged `node` child receives a randomly generated local token, never the real key. Both chat and embedding endpoints are forced to loopback. Alternate provider credentials and endpoints are excluded from the child's allowlisted environment; SDK fallback, image embeddings and automatic compression are disabled. Compression stays off for now because AgentMemory 0.9.27 indexes an observation for search only after its LLM compression succeeds: a refused, capped or failed call leaves the event stored raw but unsearchable (seen 2026-10-09: 52 refused compressions while the window was still full of the old flat reservations). `SUMMARIZE_CHUNK_SIZE=100` keeps summary chunks under the body cap. Consolidation is routed through the same guard. `/data/spend-guard` stays root-owned and inaccessible to the child.

The public AgentMemory service remains on **3111**. Its bearer secret is still generated by the original entrypoint and persisted in `/data/.hmac`; never configure a Railway service variable named `AGENTMEMORY_SECRET`. Do not print startup logs or secret files into an agent transcript.

## Two-phase first deployment

1. Preserve root `deploy/railway`, Dockerfile `Dockerfile`, version `0.9.27`, `PORT=3111`, one replica, healthcheck `/agentmemory/livez` with timeout 300, ON_FAILURE/max10, and `requiredMountPath=/data`. Attach the volume **through the Railway dashboard**.
2. Initially omit the real `OPENAI_API_KEY` and set `SPEND_GUARD_SETUP_ONLY=true`. This explicitly initializes the ledger once and starts a setup-only listener. Its liveness body is `{"status":"setup_required","inference_enabled":false}`. This is not a functioning memory deployment and makes no OpenAI calls.
3. Verify the real mount and initialized ledger without exposing `/data/.hmac`. The guard refuses initialization if an existing ledger directory is present, so damage cannot silently reset the allowance. Setup mode rejects any configured upstream key.
4. After billing authorization and mock-test validation, set the dedicated OpenAI key privately and **remove** `SPEND_GUARD_SETUP_ONLY` in the same staged change. Redeploy. Normal startup will never initialize a missing ledger.
5. Verify `/agentmemory/livez` returns 200/`{"status":"ok"}`, wrong bearer returns 401, and authenticated client memory capture/recall works. Cap errors must stop inference; storage and keyword retrieval behavior at cutoff need a live acceptance check.

No runtime knob increases the budget, switches upstream/model, skips reservations or disables ledger validation. Missing/replaced/corrupt ledger, rollback of the system clock, expired price approval, or unexpected upstream usage fail closed. Do not delete, restore an older copy of, or reinitialize the ledger to resolve an outage: restoring old reservations invalidates the spending bound. Do not roll back to an image without the guard while its real key is configured.

## Verification

`npx vitest run test/spend-guard.test.ts` exercises reservations, shared connections, concurrency at the cap, retained retries, timeout, restart persistence, month-boundary retention, clock rollback, price expiry, corruption, replacement, request restrictions, credential isolation, mount checks, and local fake HTTP upstreams. No real OpenAI key or API request is used.
